# Benchmark de búsqueda (2026-10-03)

Volumen: 10000 terceros y 10000 productos en una empresa. Calentamiento de 30 peticiones y 300 mediciones secuenciales por consulta, desde el cliente HTTP contra `main.ts`. Objetivo: P95 de 300 ms o menos en este entorno (design D16 de `add-parties-and-products`; Q-26). Generado por `bench:search`; datos en `search-2026-10-03.json`.

## Planes de consulta

| Forma de consulta                                            | Ejecución (ms) | Nodos                                                                                                                |
| ------------------------------------------------------------ | -------------- | -------------------------------------------------------------------------------------------------------------------- |
| Terceros: prefijo de identificación o fragmento de nombre    | 2.28           | Limit → Index Scan (party_company_id_status_search_name_id_idx)                                                      |
| Terceros: solo el prefijo de identificación                  | 0.05           | Index Scan (party_company_id_search_identification_idx)                                                              |
| Terceros: primera página por nombre                          | 0.05           | Limit → Index Only Scan (party_company_id_status_search_name_id_idx)                                                 |
| Productos: estado REVIEW_REQUIRED (EXISTS sobre referencias) | 1.16           | Limit → Nested Loop → Index Only Scan (product_company_id_status_search_name_id_idx) → Index Scan (product_tax_pkey) |

Todas las consultas cumplen el objetivo en este entorno.
